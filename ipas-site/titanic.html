01 專案目標

從乘客資料預測是否生還

1912 年鐵達尼號沉沒，2,224 名乘客與船員中約 1,500 人罹難。本專案用 891 名乘客的資料，建立二元分類（Binary Classification）模型，預測乘客是否生還，並解釋哪些因素影響最大。

891 筆訓練資料，12 個欄位
38.4%整體生存率（類別不平衡程度中等）
61.7%基準線 Baseline：全部猜「罹難」的準確率
83.7%調參後隨機森林的 5 折交叉驗證準確率

專案流程（CRISP-DM）

  1. 商業理解：定義目標變數 Survived，選擇評估指標（Accuracy、F1、ROC-AUC）
  2. 資料理解：檢視欄位、型別、缺失值與分布
  3. 資料準備：缺失值填補、特徵工程、編碼與標準化
  4. 建模：比較邏輯迴歸、決策樹、隨機森林
  5. 評估：交叉驗證、混淆矩陣、特徵重要性
  6. 部署與溝通：整理結論、輸出圖表與報告

發現 2：艙等反映社經地位

發現 3：家庭人數呈非線性

獨自與大家庭都偏低、2–4 人最高。線性模型抓不到這種形狀，可用分組特徵或樹模型處理。

發現 4：缺失本身也是資訊

有艙房號碼者生存率 66.7%、沒有者 30.0%。缺失與否和艙等有關，不是完全隨機缺失。
04 資料清理與特徵工程

把原始欄位變成模型看得懂的特徵

Python
import numpy as np

def add_features(d):
    d = d.copy()
    # 1) 從姓名擷取稱謂："Braund, Mr. Owen Harris" → "Mr"
    d["Title"] = d["Name"].str.extract(r",\s*([^\.]+)\.", expand=False).str.strip()
    d["Title"] = d["Title"].replace({"Mlle": "Miss", "Ms": "Miss", "Mme": "Mrs"})
    d.loc[~d["Title"].isin(["Mr", "Mrs", "Miss", "Master"]), "Title"] = "Rare"
    # 2) 家庭人數與是否獨自
    d["FamilySize"] = d["SibSp"] + d["Parch"] + 1
    d["IsAlone"] = (d["FamilySize"] == 1).astype(int)
    # 3) Cabin 缺 77%，不填補，改成「有沒有艙房號碼」
    d["HasCabin"] = d["Cabin"].notna().astype(int)
    # 4) 票價嚴重右偏，取對數
    d["LogFare"] = np.log1p(d["Fare"])
    return d

df = add_features(df)
技巧本專案做法為什麼
缺失值填補Age 用中位數、Embarked 用眾數中位數不受極端值影響；類別欄用眾數
缺失指標Cabin → HasCabin缺失比例過高，缺失與否本身有預測力
文字擷取Name → Title（正規表示式）稱謂同時包含性別、年齡、婚姻與社會地位
特徵組合SibSp + Parch + 1 → FamilySize兩個弱特徵合成一個更有意義的特徵
數值轉換Fare → log1p(Fare)降低偏態，對邏輯迴歸等線性模型有幫助
類別編碼One-Hot Encoding名目類別沒有大小關係，不能直接用 0、1、2
標準化StandardScaler（平均 0、標準差 1）邏輯迴歸、KNN、SVM 對尺度敏感；樹模型不需要

防止資料洩漏（Data Leakage）：先切分訓練集與測試集，再把填補、標準化包進 Pipeline。這樣中位數、平均數只從訓練資料計算，交叉驗證時每一折也會各自重新計算。

05 建模

Pipeline + 交叉驗證比較三種模型

Python
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score, GridSearchCV
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier

NUM = ["Age", "SibSp", "Parch", "LogFare", "FamilySize"]
CAT = ["Pclass", "Sex", "Embarked", "Title", "IsAlone", "HasCabin"]
X, y = df[NUM + CAT], df["Survived"]

# 分層抽樣 stratify：讓訓練、測試集的生存比例都維持約 38%
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)

preprocess = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")),
                      ("sc", StandardScaler())]), NUM),
    ("cat", Pipeline([("imp", SimpleImputer(strategy="most_frequent")),
                      ("oh", OneHotEncoder(handle_unknown="ignore"))]), CAT),
])

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
for name, m in {"LogReg": LogisticRegression(max_iter=1000),
                "Tree": DecisionTreeClassifier(max_depth=4, random_state=42),
                "RF": RandomForestClassifier(n_estimators=300, max_depth=6, random_state=42)}.items():
    pipe = Pipeline([("prep", preprocess), ("model", m)])
    s = cross_val_score(pipe, X_train, y_train, cv=cv, scoring="accuracy")
    print(name, round(s.mean(), 3), round(s.std(), 3))
模型5 折 CV Accuracy優點限制
Baseline（全猜罹難）0.617判斷模型是否「有學到東西」的底線完全抓不到生還者
邏輯迴歸 Logistic Regression0.822 ± 0.019可解釋（係數、勝算比），訓練快只能學線性邊界
決策樹 Decision Tree（深度 4）0.810 ± 0.016規則可視化，易向主管說明單棵樹變異大、易過擬合
隨機森林 Random Forest0.819 ± 0.020多棵樹投票，穩定、可看特徵重要性較難解釋單一預測
隨機森林（GridSearchCV 調參）0.837最佳參數：深度 4、葉節點至少 3、400 棵調參只能在訓練集上做
Python
rf = Pipeline([("prep", preprocess), ("model", RandomForestClassifier(random_state=42))])
grid = GridSearchCV(rf, {
    "model__n_estimators": [200, 400],
    "model__max_depth": [4, 6, 8],
    "model__min_samples_leaf": [1, 3],
}, cv=cv, scoring="accuracy", n_jobs=-1)
grid.fit(X_train, y_train)
grid.best_params_, grid.best_score_

為什麼測試分數比 CV 低？

CV 0.837、測試 0.793。測試集只有 179 筆，答對或答錯 1 人就差 0.56 個百分點，屬正常波動；若差距很大才需懷疑過擬合或資料洩漏。

Recall 偏低代表什麼？

69 位生還者有 23 位被誤判為罹難。若情境是「找出可能存活者去救援」，應調低分類門檻（例如 0.5 → 0.4）換取更高 Recall。

重要性被拆散

One-Hot 後 Sex 拆成兩欄、Title_Mr 又與性別高度重疊，重要性會互相分攤。解讀時要把相關欄位合併來看。
07 用 SQL 驗證

同樣的分析，用 SQL 寫一次

把 DataFrame 寫進 SQLite 記憶體資料庫，就能用 SQL 查詢；也是練習 GROUP BY、HAVING、CASE WHEN 的好題材。

Python
import sqlite3
con = sqlite3.connect(":memory:")
df.to_sql("titanic", con, index=False)
pd.read_sql("""
    SELECT Pclass, Sex,
           COUNT(*)                      AS n,
           ROUND(AVG(Survived) * 100, 1) AS survival_pct
    FROM titanic
    GROUP BY Pclass, Sex
    HAVING COUNT(*) >= 50
    ORDER BY survival_pct DESC;
""", con)

SQL
-- 依年齡層統計（CASE WHEN 分箱；Age 為 NULL 的另外歸類）
SELECT CASE WHEN Age IS NULL THEN '未知'
            WHEN Age <= 12  THEN '兒童'
            WHEN Age <= 18  THEN '青少年'
            WHEN Age <= 60  THEN '成人'
            ELSE '長者' END            AS age_group,
       COUNT(*)                        AS n,
       ROUND(AVG(Survived) * 100, 1)   AS survival_pct
FROM titanic
GROUP BY age_group
ORDER BY survival_pct DESC;

-- 視窗函數：每個艙等內票價排名前 3 的乘客
SELECT * FROM (
    SELECT Name, Pclass, Fare,
           RANK() OVER (PARTITION BY Pclass ORDER BY Fare DESC) AS rk
    FROM titanic
) WHERE rk <= 3;

考點在本專案出現的位置可能的考法
