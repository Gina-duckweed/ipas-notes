01 SQL

SQL：結構化查詢語言（Structured Query Language）

考試最愛問「書寫順序」和「執行順序」不同。理解執行順序，就能判斷為什麼 WHERE 不能用聚合函數、為什麼 SELECT 的別名在 WHERE 裡無效。

書寫順序

  1. SELECT 欄位
  2. FROM 資料表
  3. JOIN … ON
  4. WHERE 列條件
  5. GROUP BY 分組
  6. HAVING 組條件
  7. ORDER BY 排序
  8. LIMIT 筆數

實際執行順序

  1. FROM / JOIN：先決定資料來源
  2. WHERE：逐列過濾（還沒分組，不能用 SUM）
  3. GROUP BY：分組
  4. HAVING：過濾組（可用聚合函數）
  5. SELECT：計算欄位、產生別名
  6. DISTINCT：去重
  7. ORDER BY：排序（可用別名）
  8. LIMIT：取前 N 筆

範例資料表

以下範例都使用這兩張表：customers（客戶）與 orders（訂單）。

SQL
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    name        TEXT,
    city        TEXT,
    join_date   DATE
);
CREATE TABLE orders (
    order_id    INT PRIMARY KEY,
    customer_id INT,          -- 外鍵 Foreign Key，對應 customers
    order_date  DATE,
    category    TEXT,
    amount      REAL
);

1. 基本查詢與篩選

SQL
-- 台北或新竹、2026 年加入的客戶，依加入日期新到舊
SELECT name, city, join_date
FROM customers
WHERE city IN ('台北', '新竹')
  AND join_date BETWEEN '2026-01-01' AND '2026-12-31'   -- BETWEEN 含頭尾
  AND name LIKE '王%'                                   -- % 任意字元，_ 單一字元
ORDER BY join_date DESC
LIMIT 10;

2. 聚合函數與 GROUP BY / HAVING

SQL
-- 每個類別的訂單數、總金額、平均金額，只保留總金額超過 10 萬的類別
SELECT category,
       COUNT(*)              AS n_orders,      -- COUNT(*) 算列數，含 NULL
       COUNT(DISTINCT customer_id) AS n_buyers,
       SUM(amount)           AS total,
       ROUND(AVG(amount), 1) AS avg_amount     -- AVG 會忽略 NULL
FROM orders
WHERE order_date >= '2026-01-01'               -- 分組前先過濾「列」
GROUP BY category
HAVING SUM(amount) > 100000                    -- 分組後過濾「組」
ORDER BY total DESC;

3. JOIN 合併資料表

類型保留哪些列典型用途
INNER JOIN兩表都對得上的列只看「有下單」的客戶
LEFT JOIN左表全部；右表對不上補 NULL找出「從未下單」的客戶
RIGHT JOIN右表全部；左表對不上補 NULL同 LEFT，方向相反
FULL OUTER JOIN兩表全部比對兩系統資料差異
CROSS JOIN笛卡兒積（m × n 列）產生所有組合，例如日期 × 門市
SQL
-- 每位客戶的消費總額（含從未下單者，顯示 0）
SELECT c.customer_id, c.name,
       COALESCE(SUM(o.amount), 0) AS total_spent   -- NULL 轉 0
FROM customers AS c
LEFT JOIN orders AS o
       ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.name;

-- 從未下單的客戶：LEFT JOIN 後找右表為 NULL
SELECT c.name
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;

4. CASE WHEN 條件分類

SQL
SELECT order_id, amount,
       CASE WHEN amount >= 5000 THEN '高'
            WHEN amount >= 1000 THEN '中'
            ELSE '低'
       END AS level                 -- 由上往下判斷，第一個成立就停止
FROM orders;

5. 子查詢與 CTE（WITH）

SQL
-- 子查詢：金額高於整體平均的訂單
SELECT * FROM orders
WHERE amount > (SELECT AVG(amount) FROM orders);

-- CTE：把複雜查詢拆成可讀的步驟
WITH monthly AS (
    SELECT customer_id,
           strftime('%Y-%m', order_date) AS ym,   -- SQLite 日期函數
           SUM(amount) AS spent
    FROM orders
    GROUP BY customer_id, ym
)
SELECT ym, COUNT(*) AS active_customers, AVG(spent) AS avg_spent
FROM monthly
GROUP BY ym
ORDER BY ym;

6. 視窗函數 Window Function（中級重點）

視窗函數「不會把列合併」，每一列都保留，只是多一欄計算結果。這是和 GROUP BY 最大的差別。

SQL
SELECT customer_id, order_date, amount,
       ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date) AS nth_order,
       SUM(amount)  OVER (PARTITION BY customer_id ORDER BY order_date) AS running_total,
       LAG(amount)  OVER (PARTITION BY customer_id ORDER BY order_date) AS prev_amount,
       RANK()       OVER (ORDER BY amount DESC) AS amount_rank
FROM orders;
函數分數 100、90、90、80 的結果說明
ROW_NUMBER()1、2、3、4同分也給不同序號
RANK()1、2、2、4同分同名次，下一名跳號
DENSE_RANK()1、2、2、3同分同名次，不跳號

7. 資料異動（DML）

SQL
INSERT INTO customers (customer_id, name, city) VALUES (101, '陳小明', '台中');
UPDATE orders SET amount = amount * 0.9 WHERE category = '家電';   -- 少了 WHERE 會改到全表
DELETE FROM orders WHERE order_date < '2020-01-01';

SQL 分類常考：DDL 定義結構（CREATE、ALTER、DROP）、DML 操作資料（SELECT、INSERT、UPDATE、DELETE）、DCL 權限控制（GRANT、REVOKE）、TCL 交易控制（COMMIT、ROLLBACK）。

9. 應用範例：會員 RFM 分析

RFM 是常見的顧客價值分群：Recency 最近一次消費距今天數、Frequency 消費次數、Monetary 消費金額。

Python
today = df["order_date"].max() + pd.Timedelta(days=1)
rfm = df.groupby("customer_id").agg(
    R=("order_date", lambda s: (today - s.max()).days),
    F=("order_id", "nunique"),
    M=("amount", "sum"),
)
# 各指標切成 1~5 分；R 越小越好，所以標籤反過來
rfm["R_s"] = pd.qcut(rfm["R"], 5, labels=[5, 4, 3, 2, 1]).astype(int)
rfm["F_s"] = pd.qcut(rfm["F"].rank(method="first"), 5, labels=[1, 2, 3, 4, 5]).astype(int)
rfm["M_s"] = pd.qcut(rfm["M"], 5, labels=[1, 2, 3, 4, 5]).astype(int)
rfm["segment"] = np.select(
    [(rfm.R_s >= 4) & (rfm.F_s >= 4), rfm.R_s <= 2],
    ["忠誠顧客", "流失風險"], default="一般顧客")
rfm["segment"].value_counts()

06 易錯點

考題常見陷阱

WHERE vs HAVING

WHERE 在分組前過濾列，不能用 SUM、AVG；HAVING 在分組後過濾組。

NULL 的比較

要寫 IS NULL，不能寫 = NULL（結果永遠不是真）。COUNT(欄位) 不算 NULL，COUNT(*) 會算。

LEFT JOIN 後加 WHERE

在 WHERE 篩右表欄位（例如 o.amount > 0）會把補 NULL 的列刪掉，效果變成 INNER JOIN；要保留左表就把條件寫在 ON。

loc 與 iloc 切片

loc[0:3] 含結尾共 4 列；iloc[0:3] 不含結尾共 3 列。

Pandas 布林運算

要用 &、|、~ 並加括號；寫 and 會出現 ValueError（truth value is ambiguous）。

apply vs 向量化

能用欄位直接運算就不要用 apply 逐列處理，資料量大時差距可達數十倍。

inplace 與鏈式指定

df[df.a>0]["b"] = 1 可能改不到原表（SettingWithCopyWarning）；應寫 df.loc[df.a>0, "b"] = 1。

fillna 用什麼值

右偏的數值（收入、票價）用中位數；類別用眾數；時間序列用前值填補。統計量只能從訓練集計算，避免資料洩漏。

savefig 時機

plt.show() 之後畫布可能已清空，存出空白圖；先 savefig 再 show。

相關不等於因果

heatmap 只顯示線性相關（Pearson），非線性關係可能顯示接近 0。
