5.1 數據準備與模型選擇
Feature Engineering
特徵工程
透過對原始資料進行轉換、組合、選擇與生成，創造出更有助於機器學習模型預測的輸入特徵的過程。包括編碼、標準化、特徵選擇與降維。
🔍 應用場景建模前資料預處理，提升模型準確率；時序特徵、交叉特徵創建。
⚡ 考試提示特徵工程品質往往比演算法選擇更影響模型表現；「垃圾進，垃圾出」（GIGO）原則。
Principal Component Analysis
主成分分析
PCA
透過找出資料中方差最大的方向（主成分），將高維資料投影至低維空間的線性降維方法。各主成分相互正交，保留原始資料最多資訊量。
🔍 應用場景高維資料視覺化、特徵壓縮、去除共線性特徵、降低計算負擔。
⚡ 考試提示PCA 適合後續建模；t-SNE/UMAP 只適合視覺化（非線性，無法用於預測）。
Logistic Regression
邏輯迴歸
用於二元或多元分類的監督式學習模型，透過 Sigmoid 函數將線性組合輸出轉換為 [0,1] 機率值。適用於特徵與類別之間具線性可分性的場景。
🔍 應用場景信用評分（高/低風險）、疾病診斷、客戶流失二元分類。
⚡ 考試提示「迴歸」名稱誤導，實為分類模型；多元分類用 Softmax 延伸（Multinomial LR）。
Support Vector Machine
支持向量機
SVM
尋找使不同類別資料點之間間隔（Margin）最大化的超平面分類器。透過核函數（Kernel Trick）可處理非線性分類問題，適合高維資料。
🔍 應用場景文本分類、圖像分類、生物資訊學（基因組資料分析）。
⚡ 考試提示SVM 對高維稀疏資料表現良好；大型資料集訓練慢；支持向量（Support Vectors）是最靠近決策邊界的樣本點。
Random Forest
隨機森林
集成多棵決策樹的 Bagging（自助聚合）方法，每棵樹用隨機子樣本與隨機子特徵訓練，最終以投票（分類）或平均（迴歸）整合預測，有效降低過擬合。
🔍 應用場景信用風險、醫療診斷、股市預測、特徵重要性評估。
⚡ 考試提示Random Forest 提供 Feature Importance 分數，可用於特徵選擇；抗噪聲與過擬合能力強。
Gradient Boosting
梯度提升
集成學習方法，透過序列地訓練多棵弱分類器（通常是決策樹），每棵新樹修正前一棵樹的殘差（Residual），逐步提升模型準確率。代表：XGBoost、LightGBM、CatBoost。
🔍 應用場景結構化資料競賽冠軍解法、金融風控評分、點擊率預測。
⚡ 考試提示Gradient Boosting 序列訓練（不可並行）；Random Forest 可並行訓練。XGBoost 是 Gradient Boosting 的優化實作。
K-means Clustering
K 均值分群
將資料點分配到 K 個群集（Cluster）的非監督式學習演算法，透過最小化每個點到所屬群集中心點（Centroid）的距離，迭代更新群集劃分直到收斂。
🔍 應用場景顧客市場分群、文件主題分類、圖像色彩量化、異常偵測前處理。
⚡ 考試提示K-means 需預先指定 K 值（用 Elbow Method 選擇）；對初始點敏感；不適合非球形群集。
DBSCAN
基於密度的分群演算法
Density-Based Spatial Clustering of Applications with Noise，基於密度的分群方法，能識別任意形狀的群集，並自動將低密度區域的離群點標記為「雜訊（Noise）」。
🔍 應用場景地理資料分析、異常點偵測、任意形狀群集發現。
⚡ 考試提示DBSCAN 無需預設群集數（K-means 需要）；能自動處理異常點；對高維資料效果較差。
AutoML
自動化機器學習
自動執行機器學習流程（特徵工程、模型選擇、超參數調優）的技術與工具。代表平台：Google AutoML、H2O.ai、AutoKeras、TPOT。降低 AI 開發的技術門檻。
🔍 應用場景非專業資料科學家快速建模、企業快速原型驗證、AutoML 輔助特徵創建。
⚡ 考試提示AutoML 優勢：加速流程、降低門檻、高模型效能；局限：黑盒缺乏可解釋性、計算資源消耗大。
One-hot Encoding
獨熱編碼
將類別型特徵（Categorical Feature）轉換為二進位向量的編碼方式。每個類別對應一個位置，該類別為 1、其餘為 0。適用於無序類別（如顏色、城市）。缺點：高基數類別導致維度爆炸（Curse of Dimensionality）。
🔍 應用場景城市名稱、產品類別、用戶職業等無序類別特徵的前處理；搭配 Logistic Regression、SVM 等模型。
⚡ 考試提示One-hot vs Label Encoding：Label Encoding 適用有序類別（如評分1-5）；One-hot 適用無序類別（避免模型誤判數值大小的意義）；Target Encoding 用類別的目標均值替代，避免維度膨脹。
Imputation
遺漏值填補
處理資料集中缺失值（Missing Values）的技術。常見方法：均值/中位數/眾數填補（適合 MCAR 隨機缺失）、前向/後向填補（適合時序資料）、線性插補、KNN 填補（依相似樣本填補）、MICE 多重插補（多次迭代建模）。
🔍 應用場景感測器資料斷訊填補、用戶問卷部分填答處理、醫療記錄缺失欄位補全。
⚡ 考試提示填補策略選擇依缺失機制：MCAR（完全隨機缺失）用均值；MAR（隨機缺失）用模型預測；MNAR（非隨機缺失）需謹慎；刪除策略（listwise deletion）在資料量夠大且缺失比例低時可用。
Cross-validation
交叉驗證
CV
將資料集切分為 k 份（k-fold），輪流以一份為驗證集、其餘訓練，最終平均 k 次結果作為模型效能估計。避免單次分割的隨機偏差，更可靠地評估模型泛化能力。常見：5-fold、10-fold、留一法（LOOCV）。
🔍 應用場景模型選擇與超參數調優時的評估標準；資料量少時（如醫療小樣本）的穩健評估方案。
⚡ 考試提示Cross-validation 用於模型選擇，最終以全部訓練資料重新訓練；避免 Data Leakage（資料洩漏）：前處理（標準化、填補）應在每折訓練集內計算，不能在整體資料上先做。
t-SNE / UMAP
高維降維視覺化
t-SNE
t-SNE（t-distributed Stochastic Neighbor Embedding）與 UMAP（Uniform Manifold Approximation and Projection）是非線性降維技術，將高維資料投影至 2D/3D 空間以視覺化聚類結構。t-SNE 保留局部結構；UMAP 速度更快且保留全局結構。
🔍 應用場景深度學習特徵向量視覺化、顧客分群結果呈現、生物資訊（單細胞 RNA 分析）。
⚡ 考試提示t-SNE/UMAP 僅用於視覺化，不適合作為後續建模的特徵（因非線性轉換無法反向映射）；PCA 適合保留最大變異方向的線性降維，可用於後續建模；考試三者對比必記。
Data Augmentation
資料增強
透過對現有訓練資料進行變換（翻轉、旋轉、裁剪、亮度調整、加噪聲等）人工擴增資料集規模，減少過擬合、提升模型泛化能力。NLP 場景包括同義詞替換、回譯（Back-translation）。
🔍 應用場景醫療影像分類（資料量不足場景）、工業缺陷偵測、CV 模型訓練；NLP 中資料稀少的低資源語言任務。
⚡ 考試提示Data Augmentation 是解決資料不足問題的核心手段（另有 Transfer Learning、GAN 生成合成資料）；增強策略需保留語義（如語義分割任務中 mask 需同步轉換）；過度增強可能引入雜訊。
5.2 AI 系統集成與部署
Data Pipeline
資料管線
自動化的資料處理流程，涵蓋資料擷取（Extract）、格式轉換（Transform）、清理與入庫（Load），即 ETL 流程。確保資料持續穩定流入模型推論或訓練環境。
🔍 應用場景AI 系統實時推論所需的特徵計算、批次訓練資料準備。
⚡ 考試提示Data Pipeline = ETL 流程自動化；需考慮資料品質監控、缺失資料處理和延遲容忍度設計。
RESTful API
REST 風格 API
基於 HTTP 協議的應用程式介面設計風格，使用標準動詞（GET/POST/PUT/DELETE）和 URL 資源路徑，讓 AI 模型推論結果能被前端應用或其他服務呼叫。
🔍 應用場景AI 推論服務封裝（Flask/FastAPI）、模型 API 供前端/APP 呼叫。
⚡ 考試提示REST 適合一般請求；gRPC 適合高效能雙向通訊；Webhook 用於事件驅動的非同步通知。
Docker / Kubernetes
容器化與容器編排
Docker 將應用程式與依賴環境封裝為容器映像，確保跨環境一致性。Kubernetes（K8s）管理大量容器的部署、擴縮、負載平衡與故障恢復，是雲端原生 AI 部署標準架構。
🔍 應用場景AI 模型跨平台部署、微服務架構、高可用性推論服務。
⚡ 考試提示Docker 解決「在我機器上能跑」問題；K8s 解決「大規模管理」問題；Rolling Update 零停機更新。
Microservices Architecture
微服務架構
將單一應用程式拆分為多個小型、獨立的服務，每個服務實作單一功能，可獨立部署、擴展與更新。各服務透過 API 相互溝通，具備高容錯性與彈性。
🔍 應用場景大型 AI 系統拆分（推論服務/特徵計算/資料管線分離）、跨團隊並行開發。
⚡ 考試提示微服務優點：單一模組故障不影響全系統；挑戰：模組間 API 設計複雜、分散式管理難度高。
CI/CD
持續整合與持續部署
CI（Continuous Integration）：程式碼/資料變動自動觸發訓練和測試流程。CD（Continuous Deployment）：通過測試門檻後自動部署至生產環境，降低人為錯誤。
🔍 應用場景MLOps 模型迭代更新、AI 產品持續交付、避免人工部署失誤。
⚡ 考試提示MLOps = DevOps + ML；CI/CD 是 MLOps 的核心實踐，搭配 MLflow 實現模型版本追蹤。
MLflow
機器學習實驗管理平台
開源 MLOps 平台，提供實驗追蹤（Experiment Tracking）、模型版本管理（Model Registry）、模型部署與專案管理四大核心功能，記錄每次訓練的參數、指標與模型工件。
🔍 應用場景資料科學團隊實驗管理、模型版本比較、模型上線審核。
⚡ 考試提示MLflow 追蹤「模型版本」；DVC 追蹤「資料集版本」；兩者互補，共同實現 ML 可重現性。
Blue-Green Deployment
藍綠部署
維護兩個完全相同的生產環境（藍色：當前版本，綠色：新版本），部署時將流量切換至綠色環境，若發生問題可立即切回藍色，實現零停機更新與快速回滾。
🔍 應用場景AI 模型重大版本更新、零停機服務切換、快速回滾保障。
⚡ 考試提示Blue-Green：瞬間切換全量流量（低風險）；Canary：逐步灰度發布，小比例驗證後再全量。
Canary Deployment
金絲雀部署
將新版本模型先部署至一小部分用戶（如 5% 流量），監控效能指標無異常後再逐步擴大比例，最終全量切換。降低新版本問題的影響範圍。
🔍 應用場景AI 推薦系統更新、LLM 新版本灰度測試、A/B 測試整合。
⚡ 考試提示Canary 名稱源自「礦坑金絲雀」預警概念；與 A/B Test 相比，Canary 更注重風險控制而非統計比較。
Edge Computing
邊緣運算
在靠近資料產生端的裝置（IoT 感測器、手機、車載系統）上進行模型推論的運算模式，將計算從雲端中心移至邊緣，大幅降低延遲並保護資料隱私。
🔍 應用場景工廠即時品質檢測、自動駕駛感知決策、智慧城市監控、行動裝置 AI。
⚡ 考試提示邊緣推論特點：低延遲（Latency）、低頻寬消耗、高隱私保護；挑戰：算力有限（需模型量化/剪枝）。
Model Monitoring
模型監控
部署後持續追蹤 AI 模型在生產環境中的效能表現，偵測 Model Drift（預測分佈偏移）、Data Drift（輸入統計特性改變）及效能指標異常，及時觸發再訓練。
🔍 應用場景金融風控模型維護、推薦系統效能追蹤、醫療 AI 持續品質保障。
⚡ 考試提示監控三層：系統層（延遲/吞吐量）、模型層（準確率/F1）、業務層（ROI/轉換率）；常用工具：Prometheus + Grafana。
Inference Latency
推論延遲
AI 模型從接收輸入到返回預測結果所需的時間，是衡量 AI 系統回應速度的核心指標。高延遲影響用戶體驗，邊緣運算和模型輕量化是降低延遲的主要手段。
🔍 應用場景即時推薦系統 SLA 要求（<100ms）、自動駕駛感知決策、即時詐欺偵測。
⚡ 考試提示降低 Inference Latency 方法：模型量化（INT8）、知識蒸餾、邊緣部署、GPU加速、批次推論（Batching）。
Model Versioning
模型版本管理
追蹤並管理 AI 模型不同版本（包括訓練參數、資料集版本、評估指標、部署狀態）的系統性方法，確保模型可重現性、回滾能力與稽核追蹤。
🔍 應用場景模型迭代更新管理、A/B 測試版本比較、合規稽核要求。
⚡ 考試提示MLflow Model Registry 提供模型版本管理（Staging→Production→Archived 狀態機）；DVC 管理訓練資料版本。
API Gateway
API 閘道
位於客戶端與後端 AI 服務之間的中間層，統一處理 API 路由、身份驗證（OAuth2/JWT）、流量控制（Rate Limiting）、負載均衡與監控日誌。AWS API Gateway、Kong、Nginx 是常見實作。
🔍 應用場景AI 推論服務的統一入口管理；多模型 A/B 路由；防止 API 被惡意超量請求（DDoS 防護）。
⚡ 考試提示API Gateway vs Load Balancer：Gateway 側重請求路由與安全控制；Load Balancer 側重流量分發；AI 系統整合中，API Gateway 是暴露 ML 模型推論端點（RESTful/gRPC）的標準架構。
Data Drift
資料漂移
模型部署後，生產環境輸入資料的統計分佈發生顯著偏移（與訓練資料分佈不一致），導致模型效能下降。分為協變數漂移（輸入特徵分佈改變）與概念漂移（輸入-輸出關係改變）。需持續監控並觸發再訓練。
🔍 應用場景電商推薦系統因季節性消費習慣改變導致效果下滑；詐欺偵測模型因詐騙手法演進失效。
⚡ 考試提示Data Drift（輸入分佈改變）vs Model Drift（預測輸出分佈改變）vs Concept Drift（底層關係改變）三者區分是必考重點；偵測方法：KS 統計量、PSI（Population Stability Index）、特徵統計監控。
A/B Testing
A/B 測試
將用戶隨機分為對照組（A：現有模型）與實驗組（B：新模型），在真實流量下比較兩組的業務指標差異，以統計顯著性判斷新模型是否優於舊版本。是 AI 模型上線決策的黃金標準。
🔍 應用場景推薦系統新演算法驗證、廣告投放模型優化、LLM 回答品質比較評估。
⚡ 考試提示A/B Test vs Canary Deployment：A/B 強調統計比較（找更好的模型）；Canary 強調風險控制（安全切換）；A/B 需要足夠樣本量（統計功效 80%+）才能獲得可靠結論。
Feature Store
特徵儲存庫
集中管理、存儲和提供 ML 特徵的平台，支援特徵定義、計算、離線訓練（批次）與線上推論（即時）的一致性存取，避免訓練-服務偏差（Training-Serving Skew）。代表工具：Feast、Tecton、Hopsworks。
🔍 應用場景金融風控即時特徵計算、推薦系統用戶行為特徵復用、多個 ML 模型共享同一套特徵管線。
⚡ 考試提示Feature Store 解決的核心問題：Training-Serving Skew（訓練時特徵計算邏輯與線上推論不一致）；離線 Store 供批次訓練（如 Parquet/Hive）；線上 Store 供低延遲查詢（如 Redis）。
