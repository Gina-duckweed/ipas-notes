01 基本定義

AI Agent 是「會自己決定下一步」的系統

AI 代理人（AI Agent）以大型語言模型為推理核心，能依目標自行拆解任務、選擇並呼叫工具、觀察結果再決定下一步，直到完成任務。關鍵差別在「由模型決定流程」，而不是由人寫死流程。

類型誰決定流程能否呼叫工具典型例子考題常見判斷
聊天機器人無流程，一問一答否FAQ 問答只能回答，不能「做事」
RAG 問答固定：檢索 → 生成只做檢索內部知識庫問答需要最新資料、降低幻覺、可引用來源
工作流程（Workflow）人預先寫死步驟可以，順序固定表單自動化、RPA流程固定、可預測、易稽核時較合適
AI Agent模型動態決定可以，自主選擇延遲補償代理人、研究助理步驟不固定、需依觀察結果調整時才值得用
多代理系統多個 Agent 分工協作可以規劃 Agent + 執行 Agent + 審查 Agent任務需不同專業或平行處理時；成本與協調複雜度較高

Agent 的四個組成

  1. 推理與規劃：LLM 拆解任務、決定下一步（ReAct、任務分解、Thinking Budget）。
  2. 工具：透過 Function Calling 或 MCP 呼叫外部系統（查訂單、發郵件、寫資料庫）。
  3. 記憶：短期記憶（上下文）、長期記憶（外部儲存、共享狀態）、知識（RAG）。
  4. 護欄：最小權限、人工核准、輸入輸出過濾、稽核紀錄，限制 Agent 能做什麼。

03 核心名詞

20 個必懂名詞：一句話、考法、陷阱

ReAct

Reasoning + Acting
一句話　思考 → 行動（呼叫工具）→ 觀察結果 → 再思考，交替進行直到完成。
已考 114-3、115-3
陷阱：沒有取得「觀察結果」就執行不可逆動作（例如未查物流就退款）是錯誤步驟。

任務分解 / 規劃

Task Decomposition, Planning
一句話　把大目標拆成可執行的小步驟，再逐一完成或分派。
常與多代理一起考
陷阱：簡單、固定流程不需要讓模型規劃，用 Workflow 更穩定。

Agentic AI

Agentic AI
一句話　具備自主規劃、使用工具、持續執行能力的 AI 系統的統稱。
已考 114-4
陷阱：自主性越高，需要的護欄與人工監督越多，不是越自動越好。

多代理系統

Multi-Agent System
一句話　多個 Agent 分工，常見「協調者（Orchestrator）+ 執行者（Worker）」或階層式架構。
已考 114-3、114-4
陷阱：代理人越多不代表越準；會增加協調成本、延遲、Token 與狀態衝突。

Function Calling / Tool Use

Function Calling
一句話　模型輸出結構化的函式名稱與參數，由程式實際執行並回傳結果。
基礎概念
陷阱：模型本身不執行工具，是應用程式執行；參數錯誤要靠驗證機制擋下。

MCP

Model Context Protocol
一句話　連接 AI 應用與工具 / 資料來源的開放標準；工具伺服器實作一次，多個應用與模型共用。
已考 114-4、115-2、115-3
陷阱：MCP 不是模型壓縮、不取代身分驗證；權限仍要在伺服器端管控。

A2A

Agent2Agent Protocol
一句話　讓不同團隊、不同框架開發的 Agent 互相揭露能力、委派任務、回傳結果。
已考 114-4
陷阱：MCP 是「Agent 對工具」，A2A 是「Agent 對 Agent」，兩者互補，不要記反。

Skill

Agent Skill
一句話　把特定任務的指示、腳本與資源封裝成可重用的能力包，需要時才載入。
已考 115-3
陷阱：Skill 是封裝與重用，不是模型微調。

Router / Webhook

Router, Webhook
一句話　Router 依請求類型分派到不同流程或模型；Webhook 讓外部事件主動觸發流程。
已考 115-2
陷阱：Webhook 是「事件推送」，不是定時輪詢。

共享狀態

Shared State
一句話　多個 Agent 共同讀寫的任務資料，例如訂單狀態、已確認的條件。
已考 115-3
陷阱：同時寫入會衝突（Race Condition），要有單一事實來源、版本控制或鎖定。

上下文工程

Context Engineering
一句話　設計每一步要放進模型上下文的內容：相關資料、摘要、工具說明，而不是全部塞進去。
已考 114-4
陷阱：上下文越長不一定越好，成本與延遲上升，還可能「迷失於中段」。

短期 / 長期記憶

Short-term / Long-term Memory
一句話　短期記憶在上下文中；長期記憶存在外部資料庫，需要時檢索帶入。
中級可能考設計
陷阱：長任務「忘記」前面條件，對策是外部記憶 + 摘要化 + 檢索。

RAG / Agentic RAG

Retrieval-Augmented Generation
一句話　先檢索再生成；Agentic RAG 由 Agent 自行決定何時、查哪裡、要不要再查。
每場必考相關
陷阱：知識常變動用 RAG；要改語氣或格式才用微調。

Reranker

Reranking Model
一句話　先大範圍召回候選文件，再用重排序模型精準評分，取前幾筆給生成模型。
已考 115-3
陷阱：「召回率高但前幾名不準」的解法是加 Reranker，不是盲目增加檢索筆數。

Prompt Injection

Direct / Indirect Prompt Injection
一句話　直接注入：使用者輸入惡意指令；間接注入：惡意指令藏在 Agent 讀取的網頁、郵件、文件中。
已考 115-2、115-3
陷阱：只在提示詞寫「不要被騙」無法防範；要隔離外部內容、限制權限、敏感動作人工確認。

超額授權

Excessive Agency
一句話　Agent 擁有超出任務需要的權限或工具，被誤用或攻擊時損害擴大。
已考 115-3
陷阱：對策是最小權限原則：唯讀優先、限定範圍、移除不需要的工具。

Human-in / on / over-the-loop

Human Oversight
一句話　in：每次決策都要人確認；on：系統自動執行，人監看並可介入；over：人設定規則與整體治理。
已考 114-4、115-4
陷阱：核准節點要設在「不可逆動作」之前，且依風險分流，不是全部人工。

Agentic Coding / Vibe Coding

AI-assisted Coding
一句話　由 Agent 自主撰寫與修改程式碼；Vibe Coding 指以自然語言描述、少看程式碼的開發方式。
已考 115-1、115-2
陷阱：仍需程式碼審核、測試與安全掃描，不能直接上線。

Model Routing

Model Routing
一句話　依任務難度把請求分派給不同大小的模型，簡單任務走小模型以節省成本與延遲。
已考 115-3
陷阱：計算題要記得小模型仍有成本，例如 7 成走成本 1/10 的小模型，總成本降約 63%，不是 70%。

Thinking Budget

Reasoning Budget
一句話　限制模型推理時可使用的思考 Token 數量，在準確度與成本、延遲間取捨。
已考 115-3
陷阱：不是越大越好；簡單任務給大預算只會增加成本。

Agent 評估與可觀測性

Evaluation, Tracing
一句話　評估任務完成率、工具呼叫正確性、步驟數與成本、違規率；以追蹤記錄每一步的提示、工具、參數與結果。
中級預測重點
陷阱：公開基準測試分數高不代表在你的業務情境可用；上線前要情境測試、紅隊測試、灰階發布。

06 中級預測

中級可能怎麼考 Agent（推論）

架構設計題

給一段業務流程，問哪一步交給 Agent、哪一步保留人工核准、要用單代理還是多代理。

紀錄判讀題

給一段 Thought / Action / Observation 執行紀錄，找出哪一步出錯、缺少哪個工具呼叫。

成本計算題

Token 費用、Model Routing 節省比例、自建 vs API 損益兩平點、GPU 吞吐量需求。

安全情境題

判斷攻擊類型（直接或間接注入、超額授權），選出最完整的防護組合。

評估上線題

設計測試集、指標（完成率、工具正確率、成本、違規率）、紅隊測試與灰階發布。

可觀測性題

Agent「說完成卻沒執行」時，要記錄哪些資訊才能追查；個資如何遮罩。

解題口訣

  1. 先看動作可不可逆：退款、寄信、刪資料之前要有觀察結果與人工核准。
  2. 再看權限給多少：選項出現「完整讀寫權限」「方便開發」通常是錯的。
  3. 流程固定就別用 Agent：工具少、步驟固定，單代理或 Workflow 較佳。
  4. 外部內容一律當資料：郵件、網頁、文件中的指令不能直接執行。
  5. 最完整的選項通常是答案：同時包含測試、監控、權限、人工核准的選項。
